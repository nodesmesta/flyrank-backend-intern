# FL-07 — Asset Signal Scout (Checkpoint 1: The Working Agent MVP)

**The agent is built and it works end-to-end.** This is Checkpoint 1 of the
FL-06 capstone: a scripted agent, owned by this repo (`src/`), that completes
its core job — read a registered physical asset, scan the live market through
a real tool connection (**Bright Data MCP**: `search_engine` +
`scrape_as_markdown`), classify signals as **Opportunity / Risk / Noise** with
reasons and source URLs, and write a per-asset report — in one run, no
mid-run hand-editing.

> **Scope decision (2026-08-08, per user guidance):** the agent is our own
> code — it does NOT depend on an interactive session to be the agent. The
> FL-06 spec's scripting-path line was implemented as the delivered agent
> living in `src/` of this task and talking straight to the Bright Data MCP
> endpoint (`https://mcp.brightdata.com/mcp`) via a real MCP client — a
> self-contained pipeline, no chat middleware. This deviation is documented
> in the build log, as the task brief requires.

## 2. How to run it (from the repo root)

```bash
npm run scout:fl07     # full end-to-end scan: assets → market → classify → report
npm run capture:fl07   # record the run with asciinema (raw, unedited capture)
```

Setup once: copy `.env.example` → `.env` and put the Bright Data MCP URL/token
in it (`BRIGHT_MCP_URL`). The `.env` is git-ignored; the free LLM tier needs no
key, and even if one is present the agent only sends `Authorization` when the
key is non-empty.

Requires: `node` + `npm` at repo root; `tsx` and `@modelcontextprotocol/sdk`
are in the root `package.json` (deps follow the repo convention: root-only,
no per-task `node_modules` — verified: 56 packages added at root install,
0 vulnerabilities, `npx tsc --noEmit` clean).

## 3. What one run does (end-to-end, live)

Pipeline (`src/agent.ts`):

1. **Read** `data/input/assets.json` (Gold 1kg — idle, in a home safe).
2. **Connect** to Bright Data MCP (streamable HTTP client, `.env` token).
3. **Scan** — 3 targeted queries per asset (price trend / ways to put idle
   gold to work / risks of holding).
4. **Verify** — scrape top pages with `scrape_as_markdown` to ground claims.
5. **Classify** — LLM maps each finding → Opportunity / Risk / Noise with
   reason + source URL (strict JSON parser; 6/6 unit tests pass).
6. **Report** — write `data/reports/report-<date>.md` +
   `data/reports/signals-<date>.json`, append `data/run-log.jsonl`.

None of this is hand-edited mid-run, and the capture shows it.

Full detail in `data/build-log.md`. The story:

1. **Exploration run**: proved the market scan works.
2. **User correction #1**: the agent must be our code in `src/` — rewritten
   as a self-owned MCP client agent (+ also surfaced: Bright Data wraps tool
   output in `=====UNTRUSTED_<id>=====` marker blocks → unwrap before parse;
   LLM 401 with provided `sk-` key → OpenCode Zen free tier is no-auth;
   classifier parse fixed per user review).
3. **User correction #2**: deps belong at repo root — removed
   `FL-07/node_modules` + local manifest; root `package.json` now has
   `@modelcontextprotocol/sdk` + `scout:fl07` / `capture:fl07` scripts; root
   install audited 0 vulnerabilities; `npx tsc --noEmit` at root clean.
4. **Capture run** recorded the final version → `data/capture/run2.cast`,
   exit 0, replay verified.

**Cut from FL-06 spec, documented:** the cron scheduler (Mon/Thu 2×/week),
multi-asset batch output, and any action execution — all deferred/in-scope
for the next checkpoint only; the agent must recommend, not trade.
